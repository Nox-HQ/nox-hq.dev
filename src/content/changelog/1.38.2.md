What v1.38.1 claimed and did not have. It was released on the condition that
nothing known was open, and the audit behind that claim checked the issue
tracker, open pull requests and the recorded backlog, but not nox's own
self-scan, the repository's security alerts, or the release's provenance
against its tag. Each of those had something. This release is the second pass,
done the way the first should have been.

#### Fixed

- **Release provenance names the release.** Every SLSA attestation recorded
  `refs/heads/main`, because it was generated by a `workflow_run` from main. The
  digests were right — each named the exact tagged commit — but
  `slsa-verifier --source-tag vX.Y.Z` failed for every release through v1.38.1:
  the provenance could prove which commit built a binary, not which release it
  was. The generator now runs from the tag-triggered release workflow, and a new
  job verifies every archive **with** `--source-tag`, which is the check a
  consumer runs. The old check asserted that an attestation existed; this one
  existed, and verified, and still could not answer the question that mattered.
  Releases up to v1.38.1 keep commit-bound provenance only.

- **The CodeQL upload action was pinned to a commit that does not exist
  upstream.** `github/codeql-action/upload-sarif@33119e58` is absent from
  github/codeql-action's commits and git database, and none of its 289 v3 tags
  points at it; it still resolved in Actions, which is the shape of a commit
  reachable only through the fork network, or of rewritten history. `docs/usage.md`
  told users to copy it three times. Now v4.38.1. The remediation example pinned
  an annotated *tag object* rather than a commit, and four version comments named
  the wrong release for a correct SHA. All 24 pins were then checked: each exists
  upstream and its comment's tag resolves to it.

- **The VS Code extension could not be packaged.** `vsce` refused because
  `@types/vscode` (^1.136) exceeded `engines.vscode` (^1.91); CI only
  type-checked, so it stayed green. The types now track the engine floor — the
  code type-checks against 1.91's API, so no supported editor is dropped — and CI
  packages the extension on every run.

- **A character-set definition is not a secret.** The entropy detectors reported
  nox's own base62 alphabet. Alphabets are now recognised by density (32+
  characters, 75%+ of adjacent pairs consecutive), not by a single run: a run
  alone would also excuse a human password like `Summer12345678!`, which the
  existing tests caught. No change across the 14 rule-diff repositories.

- **The builder image and otel/sdk are current.** The Dockerfile's
  `golang:1.27-alpine` digest was two behind (Dependabot's own bump had gone
  stale while open). `go.opentelemetry.io/otel/sdk` moves to v1.45.0 for
  GHSA-8wmf-6v46-5gfg; no nox binary was affected, since the SDK is only
  selected for a dependency's tests and is not linked.

#### Changed

- **Manually dispatched publishing workflows wait for approval.** Homebrew
  publishing, the slopfeed publisher (manual runs only; its schedule is
  unaffected) and provenance backfill run behind a protected `release`
  environment. The six dispatchable workflows that publish nothing carry
  waivers stating why. nox's self-scan is now 0 active findings and 0
  degradations.
